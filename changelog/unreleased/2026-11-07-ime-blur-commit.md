- **An input method composition commits where it began when focus leaves.** As a browser does on blur, moving focus off a field mid-composition (a click, Tab, a focus request, the field going away, or the window deactivating) commits the text the field shows into it, and runs its `on_input_change` while it still has focus. A deactivation first runs the input that arrived before it, and a close or quit request commits the composition before `App::on_close_request` hears it. A composition belongs to its field's model, which keeps its identity through edits, formatting and `clear_history`. Finishing a composition ends its input method session: every event now carries its session, and one from an ended session is dropped while the current session's always arrives. `Runtime::ime` sends an event from the current session (`Runtime::ime_session`); `Runtime::ime_in` sends one from a given session, so a test or embedder can replay a stale answer. The shell stamps the platform's answer to its reset with the ended session: until the platform's next `Enabled` or `Disabled` on macOS, Windows and X11, by serial on Wayland, where Rune now runs the input method itself (text-input-v3). Windows now cancels the platform's composition, and on X11 Rune has winit apply the reset before the next key. A field the app removes keeps the composition until its model is shown again, when it commits there. An `App::on_ime` editor that loses the input method hears `Ime::Commit` with the text it showed.
