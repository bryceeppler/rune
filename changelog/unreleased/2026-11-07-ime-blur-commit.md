- **An input method composition commits where it began when focus leaves.** As a browser does on blur, moving focus off a field mid-composition (a click, Tab, a focus request, the field going away, or the window deactivating) commits the text the field shows into it, and runs its `on_input_change` while it still has focus. A deactivation first runs the input that arrived before it. A composition belongs to its field's model, which keeps its identity through edits, formatting and `clear_history`. The shell then discards the platform's composition (on Windows it now cancels it), and the runtime drops whatever the platform still sends for that session until the platform reports it over, so none of it reaches the field that took focus. On Wayland Rune now runs the input method itself (text-input-v3) to tell the compositor's old answers from new commits, and on X11 it has winit apply the reset before the next key. A field the app removes keeps the composition until its model is shown again, when it commits there. An `App::on_ime` editor that loses the input method hears `Ime::Commit` with the text it showed. A headless runtime drops input method events after such a finish until a commit arrives, as it can't hear a platform end the session.
